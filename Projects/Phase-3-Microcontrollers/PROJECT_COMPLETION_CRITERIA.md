Universal Project Completion Criteria

A project is Complete only when all of these are satisfied:

Requirements
 Project objective is clearly written.
 Hardware/software requirements are documented.
 Expected inputs and outputs are defined.
Implementation
 Core functionality works.
 Code is organized and readable.
 Relevant concepts from the phase are actually implemented.
Testing
 Normal cases tested.
 Edge/error cases tested.
 Results are recorded.
 Known limitations are documented.
Debugging
 At least one real bug/problem was investigated.
 Root cause was identified.
 Fix was implemented and verified.
Documentation
 README completed.
 Setup/build instructions included.
 Usage instructions included.
 Important design decisions explained.
 Screenshots, serial output, diagrams, or test evidence included where useful.
Git
 Project committed to Git.
 Commit history reflects meaningful progress.
 No unnecessary build artifacts or secrets committed.
Reflection
 What I learned is documented.
 Problems encountered are documented.
 Possible improvements are listed.
Phase-specific completion

For example, Phase 3 — Microcontrollers should additionally require:

 Hardware wiring verified.
 Datasheet/reference documentation consulted.
 Peripheral configuration documented.
 Serial/debug output captured.
 Firmware tested on the actual microcontroller.
 Debugging performed using appropriate tools where applicable.
